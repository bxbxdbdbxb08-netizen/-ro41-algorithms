# Трассировка строковых операций и парсинга в C#

## 1. Трассировка Trim(), затем Split(';')
**Исходная строка:** `s = "  Иванов; Петр; 85; "`

1. **После s.Trim():** удаляются ведущие и замыкающие пробелы. Строка принимает вид: `"Иванов; Петр; 85"`
2. **После s.Split(';'):** строка разделяется на массив подстрок по разделителю `;`.

### Содержимое элементов массива и их длина:
| Индекс массива | Элемент (строка) | Длина (Length) |
| :---: | :--- | :---: |
| 0 | `"Иванов"` | 6 |
| 1 | `" Петр"` *(с учетом пробела перед именем)* | 5 |
| 2 | `" 85"` *(с учетом пробела)* | 3 |

## 2. Трассировка int.TryParse для строки line = "Иванов Пётр;70;85;x"
После вызова `line.Split(';')` получается массив из 4 частей: `["Иванов Пётр", "70", "85", "x"]`.

| Индекс | Часть строки | Результат TryParse (bool) | Значение out переменной |
| :---: | :--- | :---: | :---: |
| 0 | `"Иванов Пётр"` | `false` | `0` |
| 1 | `"70"` | `true` | `70` |
| 2 | `"85"` | `true` | `85` |
| 3 | `"x"` | `false` | `0` |

* **Что вернёт TryParseScores и почему?**
  Метод вернёт `false`, так как строка содержит недопустимые для числового парсинга элементы: ФИО (`"Иванов Пётр"`) и буквенный символ (`"x"`). `int.TryParse` возвращает `false`, если строка не может быть корректно интерпретирована как число.

## 3. Сравнение создания объектов: string vs StringBuilder

### А. Конкатенация string s = ""; через s += i; в цикле for (i = 0; i < 4; i++)
Тип `string` в C# является **неизменяемым (immutable)**. Каждая операция `+=` создаёт **новый** объект в памяти.

* **Сколько всего объектов string создаётся?** 
  Всего создаётся **5** объектов `string`:
  1. Пустая строка `""` (при инициализации).
  2. На шаге `i = 0`: `"0"`
  3. На шаге `i = 1`: `"01"`
  4. На шаге `i = 2`: `"012"`
  5. На шаге `i = 3`: `"0123"`

### Б. Конкатенация через StringBuilder (sb.Append(i))
Класс `StringBuilder` использует внутренний изменяемый буфер. При добавлении данных новый объект в куче **не создаётся**.
* **Сколько объектов string создаётся в процессе sb.Append(i)?** **0** объектов `string` (новый объект `string` создаётся только один раз в самом конце при вызове `sb.ToString()`, если он вызывается).

### Таблица шагов для обоих подходов (i от 0 до 3):
| Шаг цикла (i) | string s += i (кол-во созданных string нарастающим итогом) | StringBuilder (создание новых string объектов) |
| :---: | :---: | :---: |
| Инициализация | 1 (`""`) | 0 (создан 1 объект StringBuilder) |
| i = 0 | 2 (`"0"`) | 0 |
| i = 1 | 3 (`"01"`) | 0 |
| i = 2 | 4 (`"012"`) | 0 |
| i = 3 | 5 (`"0123"`) | 0 |

## 4. Почему после s.ToUpper() без присваивания строка s не изменилась?
Строки в C# являются **immutable** (неизменяемыми). 
Метод `s.ToUpper()` не изменяет существующий объект в памяти, а создаёт и возвращает **новую** строку в верхнем регистре. Поскольку результат вызова метода нигде не сохраняется (нет присваивания вида `s = s.ToUpper();`), исходная переменная `s` продолжает ссылаться на старый неизмененный объект.
